# План разработки ALINA INKLINE

## 1. Запуск агента

- Использовать одного основного агента: **`gpt-5.6-sol` с reasoning `high`**. Это оптимальный баланс качества, самостоятельности и расхода токенов для цельной frontend-разработки. Не использовать `xhigh/max/ultra`.
- Если после двух циклов исправлений останутся архитектурные проблемы со scroll-анимациями или WebGL, привлечь `gpt-6-astra high` только для точечного аудита и ремонта.
- Навыки применять последовательно, не загружая все одновременно:
  1. Арт-дирекшн: `brand`, `design`, `design-system`, `ui-ux-pro-max`.
  2. Структура и тексты: `landing-page-design`, `copywriting`, `design:ux-copy`.
  3. Визуалы: `imagegen`, только если подходящих стоковых кадров недостаточно.
  4. Реализация: `ui-styling`, без стандартного внешнего вида shadcn.
  5. Финальный аудит: `marketing:brand-review`, `design:design-critique`, `web-design-guidelines`, `design:accessibility-review`.
- Не использовать нерелевантные campaign, email, performance-report и SEO-навыки: они не относятся к концепту и расходуют контекст.

## 2. Арт-дирекшн и содержание

- Создать оригинальный одностраничный сайт личного бренда **ALINA INKLINE — TATTOO ARTIST / TYUMEN**.
- Стиль: 70% fashion/editorial, 30% underground-zine. Использовать editorial brutalism, швейцарскую сетку, ксероксную зернистость, рваные композиции и крупную типографику.
- Палитра: бумажный `#E8E3D8`, почти чёрный `#0B0B0B`, сигнальный красный `#C41624`, приглушённый графит `#68635D`.
- Шрифты хранить локально: Oswald для крупных заголовков, Cormorant Garamond для редакционных фраз, IBM Plex Mono для микронадписей. Основной текст — русский; бренд и декоративные подписи допускаются на английском.
- Использовать 6–8 легальных стоковых фотографий и 2–3 оригинальных сгенерированных editorial-визуала. Все изображения хранить локально, обработать в единой чёрно-белой зернистой стилистике. Не выдавать сток за реальные работы Алины; добавить заметку `CONCEPT / TEMPORARY VISUALS`.
- Не использовать фейковые отзывы, цифры, награды, цены и рабочие ссылки. Стоимость обозначить как индивидуальную. Социальные кнопки оставить неактивными и управляемыми через конфигурацию.
- Сценарий страницы:
  1. Фирменное интро.
  2. Hero с брендом, городом и CTA «Обсудить тату».
  3. Короткий манифест.
  4. Полноэкранная работа.
  5. Асимметричный фотоколлаж.
  6. Горизонтальная sticky-галерея.
  7. Об Алине.
  8. Процесс: идея → эскиз → сеанс → заживление; рядом стерильность и уход.
  9. Переходная сцена с красным directional blur.
  10. Анимированный FAQ из пяти вопросов.
  11. Демо-форма записи.
  12. Финальный CTA и контакты.
- Тексты писать от первого лица: уверенно, кратко, без корпоративной речи, мата, пафосной «тёмной поэзии» и медицинских обещаний.
- Раздел «Об Алине» должен быть честным временным текстом: Алина — тату-мастер из Тюмени, работает с разными идеями, помогает адаптировать референс под тело и подготовить индивидуальное решение. Не указывать неподтверждённый стаж и достижения.

## 3. Реализация и интерфейсы

- Стек: React + TypeScript + Vite, GSAP/ScrollTrigger, Lenis и OGL для одного WebGL-эффекта. Не добавлять роутер, state manager, UI-kit или backend.
- Разделить контент и настройки:
  - `siteContent.ts`: тексты, портфолио, FAQ и этапы процесса.
  - `site.ts`: бренд, город, социальные ссылки, флаги демо-режима и настройки анимаций.
- Ввести типы `PortfolioItem`, `FaqItem`, `ProcessStep`, `SocialLink`, `BookingDraft` и `MotionProfile`.
- `BookingDraft` содержит имя, Telegram/телефон, идею, место, размер, желаемую дату, локальные имена файлов-референсов и подтверждение демо-режима.
- Форма использует React state и нативную HTML-валидацию. Отправка вызывает только локальное состояние `DEMO // ЗАЯВКА СОБРАНА`; сетевых запросов, сохранения в localStorage и загрузки файлов нет.
- Галерея раскрывает работу в доступном полноэкранном просмотре: закрытие по кнопке, Escape и клику по фону; фокус не должен уходить под модальное окно.
- README должен объяснять запуск, сборку, замену фотографий и текстов, активацию соцсетей, будущую Telegram-интеграцию и публикацию на GitHub Pages.

## 4. Анимационная система

- Эксперимент и визуальный удар — главный приоритет. Удобство остаётся страховочной сеткой: человек всегда понимает, где находится и как перейти к работам, FAQ и форме.
- Впечатление важнее стандартной структуры в hero, портфолио и переходных сценах; понятность важнее эксперимента в меню, FAQ и форме.
- Главный референс движения: `https://www.aupalevodka.com/en/`. Использовать его принципы, но не копировать сцены или материалы.
- Интро: 1–1,5 секунды при первом посещении; `ALINA` и `INKLINE` собираются из разных направлений, между слоями проходит красный blur. В рамках одной сессии повтор сокращается до 0,45 секунды.
- Использовать инерционный скролл, split-text, параллакс разных скоростей, вращение и масштабирование фотографий, clip-path раскрытия, scroll-progress и длинные sticky-сцены.
- Горизонтальная галерея управляется вертикальным скроллом; фотографии перекрываются, слегка поворачиваются и раскрываются по нажатию.
- Directional blur реализовать одним OGL-шейдером, реагирующим на скорость прокрутки. При отсутствии WebGL использовать CSS blur/transform fallback.
- На десктопе добавить инерционный красный курсор: `VIEW` над работами, стрелка над CTA, сжатие при клике. На touch-устройствах отключить.
- Фиксированная шапка скрывается при прокрутке вниз и возвращается при движении вверх. Бегущую строку и звук не использовать.
- На мобильных сохранить выразительные появления, blur, слои и движение, но сократить sticky-дистанции, отключить кастомный курсор и WebGL.
- При `prefers-reduced-motion` отключить Lenis, WebGL, длинные sticky-сцены и резкие перемещения, сохранив статичную композицию и короткие fade-переходы.
- Все GSAP-анимации создавать через контекст и полностью очищать при размонтировании.

## 5. Форма и пользовательский путь

- Фиксированная навигация: «Работы / Обо мне / Процесс / FAQ / Запись» и красная CTA-кнопка.
- Форма содержит:
  - имя;
  - Telegram или номер телефона;
  - идею татуировки;
  - место нанесения;
  - примерный размер;
  - желаемую дату;
  - выбор файлов-референсов;
  - подтверждение, что это демо-форма.
- После отправки показать оформленный экран «Заявка собрана», явно сообщив, что в концепте данные никуда не отправляются.
- FAQ раскрывается с анимацией и отвечает на пять тем: формирование стоимости, работа с референсом, подготовка к сеансу, боль и уход/заживление.
- Не делать навигацию, FAQ или форму визуальными загадками, даже если остальные секции намеренно экспериментальны.

## 6. Проверка и критерии готовности

- Добавить команды `lint`, `typecheck`, `build` и Playwright smoke-тесты.
- Проверить:
  - загрузку hero и завершение интро;
  - якорную навигацию и auto-hide шапки;
  - sticky-галерею и модальный просмотр;
  - FAQ;
  - обязательные поля, ошибки и демо-успех формы;
  - отсутствие сетевого запроса при отправке;
  - reduced-motion и WebGL fallback;
  - клавиатурную навигацию, видимый focus и Escape;
  - отсутствие ошибок консоли и случайного горизонтального overflow.
- Выполнить визуальную проверку на ширинах 1440, 1280, 390 и 360 px в актуальных Chrome, Edge, Firefox и Safari/iPhone.
- Оптимизировать изображения в AVIF/WebP, preload только hero, всё ниже первого экрана загружать лениво. Не использовать видео.
- Цель: Lighthouse ≥80 Performance и ≥90 Accessibility/Best Practices для production-сборки.
- При конфликте выбирать стабильную анимацию и быструю загрузку вместо дополнительного эффекта.
- Проект считается готовым, когда сайт выглядит экспериментально и насыщенно, но пользователь в любой момент понимает, как открыть работы, получить ответы и перейти к форме записи.

## 7. GitHub Pages

- Текущее состояние: пустой локальный Git-репозиторий без коммитов и remote; в проекте есть только папка `референсы`.
- После успешных проверок переименовать ветку в `main` и создать коммит `feat: build Alina Inkline tattoo portfolio concept`.
- Если GitHub CLI авторизован: создать публичный репозиторий `alina-inkline`, подключить remote, настроить GitHub Actions и опубликовать на GitHub Pages без отдельного домена.
- Если GitHub не авторизован: оставить полностью готовый локальный коммит и выдать одну последовательность команд для создания remote и публикации.
- Настроить Vite так, чтобы ассеты корректно работали из подпапки GitHub Pages.

## 8. Зафиксированные ограничения

- Только frontend-концепт; Telegram-бот, backend, база данных и реальная отправка заявок не входят в первую версию.
- Один длинный одностраничник без маршрутизации.
- Стоковые и сгенерированные изображения временные и позже заменяются настоящими работами Алины.
- Без отдельного домена и продвижения.
- Без звука, бегущей строки, фейковых отзывов, статистики, цен и достижений.
- Поддерживаются современные браузеры; Internet Explorer и старые устройства не входят в обязательную совместимость.
